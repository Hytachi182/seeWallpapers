# seeWallpaper 1.13.0

Two original manga scenes bring the built-in catalogue to 57 wallpapers. **Inkbound Courier** combines ink, ivory and vermilion above a coastal town; **Satin Afterglow** adds restrained adult fashion glamour on a twilight terrace. Both run offline with adjustable atmospheric animation and documented generated-art provenance. Satin Afterglow is fully clothed and non-explicit; neither theme uses franchise characters or downloaded manga artwork.

## Windows reliability

- Clicking Explorer's desktop or taskbar no longer triggers fullscreen pause. The app reads the initial fullscreen and battery state before restoring saved wallpapers, so pause preferences apply at startup.
- Display refresh restores saved Clone and Span selections when a wallpaper window has closed or lost its desktop attachment, even if the monitor layout has not changed. Active wallpaper IDs reflect actual live desktop attachment.
- Damaged or inaccessible performance settings no longer block startup. Invalid JSON is retained in a diagnostic file, defaults allow startup to continue, and temporarily inaccessible files remain available for retry.

## Validation and remaining checks

Local compilation succeeded with zero warnings and errors. The full .NET suite passed 200 tests; three opt-in desktop tests were skipped. The release-automation suite passed all 24 tests. Both new scenes passed Edge desktop/portrait rendering, every setting, pause/resume, stable character pixels, a 24-hour deterministic preview, reduced motion, speed zero, bounded 4K rendering and offline loading. Both `.seewall` archives passed CRC and byte-equality checks.

The functional desktop scenarios now include recovery of closed Clone and Span windows, but those interactive scenarios and the three opt-in desktop tests were not rerun for this release preparation. Real Explorer recovery, physical monitor reconnects, sign-in/battery behavior, sleep/resume and performance on representative GPUs still require on-device validation. Installer and portable packaging for 1.13.0 have not been validated locally; the release workflow builds and verifies those artifacts after the PR is merged. This preparation does not publish a release.
